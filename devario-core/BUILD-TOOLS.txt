Worker prerequisites and ordering
--------------------------------
These are distribution rebuild recipes. They require a working base-devel
environment and a repository that resolves their declared dependencies.
The complete declarations are in each recipe's .SRCINFO. This set does not
provide every recursive build, documentation, or test dependency.

Use the existing CMake/Ninja and Python bootstrap tools to start. CMake has
its own dependency cycle with cppdap; do not assume a build from an empty root.
Build Ninja before Meson and the LLVM tools. Meson also needs Python's build,
installer, setuptools, wheel, aiohttp, strictyaml, and tqdm packages.

Clang, LLD, and Rust target LLVM 23.1.1. The audited core snapshot already
contains llvm and llvm-libs 23.1.1. Build compiler-rt 23.1.1 from the
compiler-rt directory first; compiler-rt21 is not a substitute. Then build
Clang and LLD before Rust and Qt Tools. See compiler-rt/README.txt.
The versioned clang21/lld21 directories remain available for LLVM 21 users.

Rust requires an existing Rust/Cargo/rustfmt compiler installation, LLVM 23.1.1,
multilib libraries, AArch64 cross compilers/libraries, musl targets, wasi-libc,
and wasm-component-ld. Its upstream bootstrap configuration uses /usr/bin
tools and builds multiple target libraries. Build and publish its split outputs
together. The recipe declares check dependencies but has no check() hook;
passing --check does not run the Rust compiler test suite.

Build Rust before Ripgrep. Ripgrep's prepare() fetches Cargo.lock-pinned crates;
its build and tests use --frozen. Go-md2man needs Go and downloads its Go module
dependencies during the build. Asciidoctor needs Ruby and ruby-rdoc, plus the
declared Ruby test gems when checks are enabled.

Build Qt Tools before Extra CMake Modules (ECM uses Qt Help for documentation).
Qt Tools needs litehtml, matching Qt 6.11.2 base/declarative packages, Clang,
LLVM, CMake, Ninja, and Vulkan headers. Qt Tools and Extra CMake Modules have
no check() hook. Bash Completion, Go-md2man, and stb also have no check() hook.
Meson's upstream check dependency list is deliberately extensive and retained.

Review and build from the repository root, for example:

  shelly build --review-only --json ./devario-core/scdoc/PKGBUILD
  shelly build --isolated --check ./devario-core/scdoc/PKGBUILD

For signed sources, compare the fingerprints in validpgpkeys with the bundled
keys/pgp/*.asc files, then import the public keys as the account doing the build.
Copy the whole recipe directory to the worker so patches and keys are included.
Publish packages and refresh the repository database before dependent builds.

Validation
----------
All 13 recipes passed bash -n, makepkg --printsrcinfo, source checksum validation,
and applicable source signature validation. Validation targeted x86_64; Rust's
other host architectures were not built or validated. The only remaining SKIP
checksums in these recipes are detached signatures verified against source files.

Shelly review completed for all 13. Findings flag ordinary command substitutions,
Ruby installation into the temporary package tree, Cargo's locked dependency
fetch, and backticks in upstream patch comments. These findings were inspected.

scdoc built successfully, passed make check, and produced package archives in a
temporary directory. Qt Tools source extraction and prepare() passed. Full builds
of the remaining recipes and isolated worker builds have not been run in this
task. No host packages were installed and no packages were published.

See build-tools-validation.json for recipe hashes and validation results.
